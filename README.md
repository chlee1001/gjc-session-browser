# GJC Sessions

작업 폴더마다 흩어진 GJC 세션 JSONL을 한 화면에서 찾고, 열어 보고, 정리하는 로컬 웹 도구입니다.

`gjc stats`는 사용량 통계만 주고 세션 목록 API는 없습니다. 이 도구는 세션 JSONL을 직접 읽어 제목·대화 내용·모델·경로로 검색할 수 있는 인덱스를 만듭니다. 서버는 `127.0.0.1`에만 바인딩하며, 세션 내용은 이 컴퓨터를 벗어나지 않습니다.

> 한 가지 예외: 화면 글꼴을 Google Fonts에서 불러옵니다(`index.html`의 `<link>`). 완전한 오프라인이 필요하면 그 줄을 지우고 시스템 글꼴로 폴백시키세요. 세션 데이터가 나가는 것은 아닙니다.

![세션 인덱스](docs/list.png)

## 무엇을 하나

검색은 제목만 훑지 않습니다. 대화 본문과 작업 폴더 경로, 모델명까지 한 인덱스에 넣어 두고 찾습니다. 공백으로 나눈 여러 단어는 AND로 묶입니다.

기본으로 **최근 1주**만 봅니다. 사이드바 기간 드롭다운으로 오늘·3일·1주·1개월·3개월·전체를 고르거나, 직접 지정으로 시작·종료 날짜를 잡습니다. 위 통계와 작업 폴더 목록, 상태 칩 숫자도 고른 기간을 따릅니다.

통계 아래 **모델별 사용량** 은 같은 기간의 토큰을 모델로 쪼갠 표입니다. 인덱스가 첫 화면을 차지하도록 기본은 접혀 있고, **모델 N개 보기** 로 펼칩니다. 토큰·비중·비용·응답 수·세션 수를 모델마다 보여 줍니다.

모델 행의 **세션 보기** 를 누르면 그 모델을 쓴 세션이 모달로 열립니다. 세션마다 비중·토큰·비용과 작업 미리보기, 상태 표시를 보여 줍니다. 행을 누르면 모달을 갈아끼우며 그 세션 상세로 넘어가고, 상세를 닫으면 눌렀던 모델 행으로 돌아옵니다.

세션 헤더의 모델이 아니라 **응답 메시지에 적힌 모델** 로 나눕니다. 세션 하나가 도중에 모델을 갈아탉니다. 서브에이전트는 대개 다른 모델을 씁니다. 그래서 세션 파일 옆 아티팩트 폴더의 서브에이전트 전사본까지 읽어 그 세션의 몫으로 더합니다. 상단 토큰·비용 통계와 목록의 세션별 수치도 같습니다. 이 저장소에서는 서브에이전트 몫이 전체 토큰의 28%였습니다. 본문만 읽으면 아예 보이지 않는 모델도 두 개 더 나왔습니다.

모델별 세션 수를 다 더하면 전체 세션 수보다 클 수 있습니다. 한 세션이 여러 모델에 걸치기 때문입니다. 목록 행에는 토큰을 가장 많이 쓴 모델이 뜨고 나머지는 `외 N` 으로 붙습니다. 세션 상세에는 모델별 내역과 서브에이전트 몫이 따로 보입니다.

세션에는 **작업 중** 과 **완료** 표시를 달 수 있습니다. 둘은 배타적이라 하나를 켜면 다른 하나는 풀립니다. 끝났지만 지우기는 아까운 세션을 완료로 빼놓습니다.

사이드바 상태 칩은 여러 개를 함께 고를 수 있습니다. `표시 없음` 과 `작업 중` 을 같이 고르면 완료만 빠집니다. 아무것도 고르지 않으면 전부 보입니다. 칩 숫자는 나머지 조건을 적용한 뒤의 개수라, 누르면 그만큼 나옵니다. 표시 자체는 세션 원본이 아니라 별도 설정 파일에 저장합니다.

바로 아래 `현재` · `보관됨` · `모두` 칩이 보관 범위를 정합니다. 상태와 같은 칩 문법이라 걸러보는 방법을 따로 외우지 않아도 됩니다. 검색어·상태·보관 범위·기간·작업 폴더 중 하나라도 걸려 있으면 칩 아래에 **필터 초기화** 가 나타나 한 번에 해제합니다.

보관 직후에는 30초 동안 되돌릴 수 있으며, 되돌리면 권위 목록을 처음부터 다시 불러옵니다.

여러 개를 한 번에 보관하려면 목록 오른쪽의 **선택** 을 켭니다. 그때만 행에 체크박스가 붙고 일괄 보관 줄이 뜨며, 한 번에 최대 200개까지 처리합니다. 보관은 되돌릴 수 있는 동작이라 확인 단계를 두지 않고 바로 실행한 뒤 단건과 같은 30초 되돌리기를 줍니다.

보관·상태·제목 변경 뒤에는 화면에 이미 쌓인 실제 행 수를 다음 페이지 오프셋으로 사용하고, 서버의 요약 전용 응답으로 결과 개수와 통계만 다시 확인합니다. 예상 개수와 서버 개수가 다르면 일부 행을 억지로 맞추지 않고 첫 페이지부터 다시 불러옵니다.

목록은 최근 활동순 외에 토큰 많은순과 비용 높은순으로 정렬할 수 있습니다. 어떤 모델이 비싼지뿐 아니라 어떤 세션·작업이 비용을 만들었는지 바로 찾을 때 씁니다.

전체 인덱싱이 끝나기 전에는 아직 본문을 읽지 않은 세션의 토큰·비용이 0으로 표시되므로 토큰·비용순에서 뒤로 밀립니다. 인덱싱 완료 시 목록을 다시 정렬합니다. 최근 활동순에서 보이는 세션의 제목을 바꾸면 다음 목록 갱신 전까지 행 위치는 그대로일 수 있습니다.

기본 경로 밖에 세션이 있으면 환경변수와 CLI, UI 어느 쪽으로든 폴더를 더합니다.

세션이 3,000개를 넘어도 화면은 가상 스크롤로 보이는 행만 그립니다. 서버는 50개씩 끊어 보냅니다.

### 상세 보기

행을 클릭하면 목록에서 잘렸던 정보 전체와 세션 파일 경로, 마지막 사용자·어시스턴트 대화가 열립니다. 같은 화면에서 제목을 바꾸거나 세션을 보관·복원하거나 영구 삭제합니다.

영구 삭제는 보관과 다릅니다. 먼저 같은 논리 세션 ID로 발견된 모든 원본 사본과 연결 아티팩트 경로를 보여 주고, 고정 확인 문구를 입력해야 실행됩니다. 성공하면 그 세션의 원본·아티팩트·사용량이 모두 사라집니다. 일부만 삭제된 경우 남은 경로와 재시도 동작을 표시합니다. 재시도 상태는 현재 서버 프로세스에만 있으므로 부분 실패 상태에서 서버를 다시 시작하면 자동 복구되지 않습니다.

화면에서는 `영구삭제`를 입력하지만 서버 요청에는 선택한 세션 ID를 확인값으로 보냅니다. 삭제 직전에 서버가 모든 경로와 권한을 다시 확인하므로 먼저 열어 둔 삭제 범위 화면이 삭제 권한을 대신하지 않습니다.

## 요구 사항

| 항목 | 용도 | 필수 여부 |
| --- | --- | --- |
| Node.js | 서버·빌드·테스트 | 필수 (v22.14.0에서 검증) |
| GJC 세션 JSONL | 읽을 대상 | 필수 |
| Bun + `@gajae-code/coding-agent` | 제목 변경·삭제 | 선택 |

제목 변경과 삭제는 GJC가 설치된 패키지의 `SessionManager` / `FileSessionStorage`를 Bun으로 호출합니다. Bun이나 GJC 패키지가 없으면 조회·검색·북마크는 그대로 되고 변경·삭제만 실패합니다.

## 실행

```bash
npm install
npm run build
npm start
```

`http://127.0.0.1:4175` 을 엽니다.

개발 중에는 Vite 미들웨어가 붙은 모드로 실행합니다. 상시 서비스와 겹치지 않게 `4176`을 씁니다.

```bash
npm run dev
```

상시 띄워 둔다면 아래 **상시 실행** 을 쓰세요. 개발 모드는 Vite 변환 비용을 계속 물고 갑니다.

## 상시 실행 (macOS)

`scripts/service.sh` 가 빌드하고 LaunchAgent로 등록합니다. 등록하면 로그인할 때마다 자동으로 뜨고, 죽으면 launchd가 다시 띄웁니다.

```bash
./scripts/service.sh install    # 빌드 + 등록 + 시작
./scripts/service.sh status     # 등록·실행·응답 상태
./scripts/service.sh stop       # 지금 종료
./scripts/service.sh start      # 지금 시작
./scripts/service.sh restart
./scripts/service.sh update     # 코드 바꾼 뒤 재빌드 + 재시작
./scripts/service.sh logs 100
./scripts/service.sh uninstall  # 자동 시작 해제
```

`stop` 은 지금 멈출 뿐이고 다음 로그인에 다시 뜹니다. 자동 시작을 아예 끄려면 `uninstall` 입니다.

포트를 바꾸려면 `GJC_SESSION_LIST_PORT=5000 ./scripts/service.sh install` 처럼 지정한 뒤 등록하세요.

| 항목 | 위치 |
| --- | --- |
| LaunchAgent | `~/Library/LaunchAgents/com.gjc.session-list.plist` |
| 표준 출력 | `~/Library/Logs/gjc-session-list.out.log` |
| 표준 오류 | `~/Library/Logs/gjc-session-list.err.log` |

plist에는 `node`와 `bun`의 절대 경로가 박힙니다. launchd는 로그인 셸의 `PATH`를 물려받지 않기 때문입니다. nvm으로 node 버전을 올렸다면 경로가 바뀌니 `install` 을 다시 실행하세요. `status` 가 그 상황을 잡아 알려 줍니다.

## 세션 경로 설정

기본값은 `~/.gjc/agent/sessions` 입니다. 홈 디렉터리 전체를 훑지 않으니 다른 위치는 직접 알려 줘야 합니다.

```bash
# 환경변수 (단일)
GJC_SESSION_DIR=/path/to/sessions npm start

# 환경변수 (여러 개, OS 경로 구분자)
GJC_SESSION_DIRS="/path/one:/path/two" npm start

# CLI (반복 지정 가능)
npm start -- --session-dir /path/one --session-dir /path/two
```

UI 좌측 **저장소 → 세션 경로 추가** 로 넣은 경로는 `~/.gjc/session-list.json` 에 저장돼 다음 실행에도 유지됩니다.

| 환경변수 | 뜻 |
| --- | --- |
| `PORT` | 수신 포트 (`npm start`·서비스는 `4175`, `npm run dev`는 `4176`) |
| `GJC_SESSION_DIR` | 세션 폴더 하나 추가 |
| `GJC_SESSION_DIRS` | 세션 폴더 여러 개 추가 (OS 경로 구분자, POSIX는 `:`) |
| `GJC_CODING_AGENT_DIR` | GJC 에이전트 디렉터리 (기본 `~/.gjc/agent`) |
| `GJC_PACKAGE_DIR` | GJC 패키지 위치 직접 지정 (자동 탐색 실패 시) |

## 동작 방식

첫 요청에서 두 단계로 인덱싱합니다. 먼저 각 JSONL의 첫 줄만 읽어 제목과 경로, 시각을 만들고 목록을 바로 띄웁니다. 그 다음 백그라운드에서 전체를 파싱해 대화 검색용 텍스트와 토큰·비용을 채웁니다. 진행률은 상단에 표시됩니다.

결과는 `~/.cache/gjc-session-list/index-v4.json.gz` 에 gzip으로 저장합니다. 다음 실행에서는 파일 크기와 `mtime`이 그대로인 세션을 다시 파싱하지 않습니다. 세션 본문은 그대로인데 서브에이전트만 늘어난 경우를 놓치지 않으려고 전사본은 개수·총 크기·최신 `mtime` 을 지문으로 같이 봅니다.

같은 세션 id가 두 번 나오면 한 줄만 남깁니다. GJC 저장소 마이그레이션 잔재로 같은 세션이 구형 `-경로인코딩` 폴더와 신형 `v2-해시` 폴더에 동시에 남아 있기 때문입니다. 둘 다 올리면 목록이 중복되고 토큰도 두 번 섽니다. 최근 활동이 늦은 사본을 남깁니다. 시각까지 같으면 더 긴 쪽입니다.

파일 감시자는 두지 않습니다. 갱신 시점은 서버 시작, **다시 스캔** 버튼, 세션 경로 추가 세 가지뿐입니다.

### 실측치

세션 파일 198개 (중복 사본 6개를 걸러 목록에는 192개) + 서브에이전트 전사본 2,931개, 합 3.1 GB / Apple M3 Pro:

| 항목 | 값 |
| --- | --- |
| 첫 목록 응답 | 약 0.2초 |
| 인덱싱 완료 (캐시 적중) | 약 0.3초 |
| 인덱싱 완료 (캐시 없음) | 약 13초 |
| 캐시 크기 | 약 1.8 MB |
| 인덱싱 중 최대 메모리 | 약 174 MB |
| 유휴 메모리 | 약 77 MB |

캐시가 없는 첫 실행은 전사본까지 다 읽어 13초가 걸리지만 그동안에도 목록은 0.2초에 뜨고 상단에 진행률만 보입니다. 큰 세션 하나가 바뀐 뒤에는 그 세션과 전사본만 다시 읽어 2~3초입니다.

세션 파일 `<이름>.jsonl` 옆의 같은 이름 디렉터리는 그 세션의 아티팩트 폴더입니다. 안에 서브에이전트 전사본이 `.jsonl` 로 들어 있지만 독립 세션이 아니므로 **목록에는 올리지 않고**, 그 안의 **토큰과 비용은 부모 세션에 합산**합니다.

## 데이터

| 경로 | 내용 | 지워도 되나 |
| --- | --- | --- |
| `~/.gjc/agent/sessions/**.jsonl` | 세션 원본 | 지우지 마세요. 이 도구는 읽기만 하고, 제목 변경·삭제 요청에만 GJC API로 수정합니다 |
| `~/.gjc/session-list.json` | 추가한 세션 경로, 세션별 상태(작업 중/완료), 보관 ID | 지우면 표시·보관·경로 설정이 사라집니다 |
| `~/.cache/gjc-session-list/index-v4.json.gz` | 검색 인덱스 캐시 | 언제든 지워도 됩니다. 다음 실행에 다시 만듭니다 |

## API

전부 `127.0.0.1` 로컬 전용입니다.

| 메서드 | 경로 | 설명 |
| --- | --- | --- |
| `GET` | `/api/sessions` | 목록. `q`, `folder`, `status`(쉼표 구분), `archive`(`current`·`archived`·`all`), `sort`(`recent`·`tokens`·`cost`), `from`·`to`(UTC ISO), `offset`, `limit`(≤100), `summaryOnly=1`, `refresh=1` |
| `GET` | `/api/sessions/:id` | 상세 + 마지막 대화 |
| `PATCH` | `/api/sessions/:id` | 제목 변경. 본문 `{ "title": "..." }` (1~120자, 제어문자 불가) |
| `DELETE` | `/api/sessions/:id` | 삭제. 본문 `{ "confirm": "<세션 ID>" }` 가 정확히 일치해야 합니다 |
| `GET` | `/api/sessions/:id/delete-preflight` | 영구 삭제 전 원본·아티팩트 경로와 권한 범위 확인 |
| `PUT` | `/api/status/:id` | 상태 변경. 본문 `{ "status": "active" \| "done" \| "none" }` |
| `PUT` | `/api/archive/:id` | 보관·복원. 본문 `{ "archived": true \| false }` |
| `PUT` | `/api/archive` | 명시한 ID 일괄 보관·복원. 본문 `{ "ids": ["..."], "archived": true \| false }` (최대 200개·8,000바이트) |
| `GET` | `/api/models/sessions` | 모델별 세션 지연 조회. `model`, `from`, `to`, `offset`, `limit`, `revision` |
| `POST` | `/api/directories` | 세션 경로 추가. 본문 `{ "path": "..." }` |

`/api/sessions` 응답의 `summary.models` 는 기간 안의 토큰·비용을 모델별로 나눈 배열입니다. 세션마다 붙는 `models` 는 그 세션 몫입니다. 둘 다 서브에이전트를 포함하며 세션·상단 합계도 같은 모델 버킷에서 계산합니다. 보관 필터는 목록 행만 바꾸고 기간 통계에는 영향을 주지 않습니다. 서브에이전트 몫만 따로 보려면 세션의 `subagentTokens` · `subagentCost` 를 쓰세요.

목록의 `sort` 값은 세 값만 받으며 다른 값은 `400 invalid_sort`로 거부합니다. 일괄 보관은 필터를 서버에서 다시 해석하지 않고 요청의 ID만 처리합니다. 한 번의 설정 쓰기와 revision 변경으로 커밋하고, ID별 결과는 `changed`·`noop`·`not_found`로 돌려줍니다. 전부 `noop`이면 설정 파일과 revision을 바꾸지 않습니다.

`/api/models/sessions` 는 **세션 보기** 를 누를 때만 호출합니다. 첫 페이지 응답의 `revision`을 다음 페이지에 다시 보내야 하며, 인덱스가 바뀐 옛 revision은 `409 stale_revision`으로 거부됩니다. 클라이언트는 옛 행과 새 행을 섞지 않습니다.

모달을 열어 둔 상태에서 revision이 바뀌면 기존 행을 즉시 버리지 않고 오래된 데이터로 표시하며 **새로 보기** 를 제공합니다. 새로 보기 전에는 더 불러오기를 막습니다.

모달의 각 행에는 최대 160자의 작업 미리보기와 해당 모델 토큰에서 차지하는 비중을 표시합니다. 파일 경로, 전체 대화, 다른 모델 사용량과 세션 전체 합계는 이 지연 조회 응답에 넣지 않습니다. 그 내용이 필요하면 행을 눌러 세션 상세로 넘어갑니다.

제목 변경과 삭제는 인덱싱이 끝난 뒤에만 받습니다 (진행 중이면 `409`).
